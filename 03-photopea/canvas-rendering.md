# Photopea · 画布渲染模型

> 维度四：图层、坐标系、渲染与导出序列化。Photopea 的渲染以 `<canvas>` 为唯一图像表面（[OBS]）。

## 1. 渲染表面（[OBS]）

观察 `photopea-editor-doc.json`：文档打开后页面存在 **3 个 `<canvas>`**：
- 主画布 `1011 × 951`：文档实际像素表面（即「画布大小」对应的可视区）。
- 两个小 canvas（34×34、32×18）：应为**工具/光标预览或状态指示**（如画笔光标、缩放指示），属 UI 辅助层。

> 结论：图像与编辑内容绘制在**单一主 `<canvas>`**，UI chrome（菜单/工具/面板）为 DOM 环绕四周。这与 Canva（元素多为 DOM/SVG）形成根本差异。

## 2. 图层与合成（[INF]，基于 PSD 内核）

- 渲染时按**图层堆叠顺序自底向上合成**，每层套用混合模式（正常/溶解/变暗/正片叠底… [OBS]）与不透明度/填充。
- 蒙版、剪贴组、调整层在合成管线中作为**非破坏性节点**参与，结果写入主画布像素（[INF]）。
- 文字层、形状层以**矢量**存储，渲染时栅格化到主画布（[INF]，对应 文字 T / 矩形 U / 钢笔 P）。

## 3. 坐标系（[INF]）

存在两层坐标：
- **文档坐标**：与画布「画布大小」绑定，元素/图层位置以文档像素表示。
- **视图坐标（屏幕）**：由「缩放 + 平移（抓手 H / 缩放 Z）」构成的视图变换矩阵映射而来。
- 命中测试在**视图坐标 → 文档坐标反变换**后，再对模型做判定（见 `events.md`）。

## 4. 脏矩形与性能（[INF]）

- 自研渲染通常只重绘**脏区域（dirty rectangle）**或分层缓冲，避免每帧全量重绘（对画笔连续描边尤其关键）。
- 选项栏参数（如画笔流量）实时作用于渲染缓冲，松手再提交历史（见 `state-dataflow.md` / `events.md`）。

## 5. 导出与序列化（[OBS] + [DOC]）

- 文件菜单（`photopea-menu-文件-dropdown.json`）提供：`新建项目` `从电脑打开` `模板` `安装 Photopea` `Generate Video`，隐含导出/导入入口。
- 基于 PSD 内核（新建文档默认 `新建项目.psd`，[OBS]），可导入/导出 **PSD、PXD、AI 近似、SVG、PDF** 等，并导出位图 **PNG/JPG/GIF/WebP/BMP/TIFF** 等（[DOC] 官方特性页）。
- **序列化 = 文档模型 → 文件格式**：PSD 兼容意味着其内存模型与 Photoshop 文件结构高度同构（[INF]）。

## 6. 与 Canva 渲染模型对比（预告）

| 维度 | Photopea | Canva |
| --- | --- | --- |
| 图像表面 | 单一 `<canvas>`（像素/矢量合成） | DOM/SVG 元素（元素即对象） |
| 坐标 | 文档坐标 + 视图矩阵 | 元素布局坐标（相对页面） |
| 导出 | PSD/位图等，本地生成 | 云端渲染导出 PNG/PDF 等 |
| 非破坏编辑 | 调整层/蒙版/混合模式 | 元素属性编辑、模板变量 |

详见 `04-comparison.md`。
