# Photopea · 状态与数据流

> 维度二：选中态、撤销栈、文档模型、数据流。Photopea 内部为黑盒，以下以**观察 + Photoshop 等价架构推断（[INF]）**为主，凡可观察处均标 `[OBS]`。

## 1. 文档模型（[INF]，基于 PSD 内核与观察）

Photopea 文档是 **Photoshop 文档（PSD）在内存中的等价物**：
- 一个文档 = 一棵 **图层树**（Layer Tree），根下挂背景层、普通层、文字层、形状层、调整层、蒙版、组（文件夹图层）等。
- 图层属性：混合模式（正常/溶解/变暗/正片叠底…）、不透明度、填充、锁定、可见性（[OBS] 面板控件）。
- 额外通道（通道面板）、路径（路径面板）、历史（历史记录面板）均为文档的并行数据结构（[OBS] 面板存在即证明结构存在）。
- 新建文档默认命名 `新建项目.psd`（[OBS]），直接暴露其 PSD 内核身份。

## 2. 选中态（Selection State，[INF]）

存在多套「选中」：
- **工具选中态**：当前激活工具（工具栏 `toolbtn.active`，[OBS]）。
- **图层选中态**：图层面板高亮项，决定后续操作作用对象（[INF]）。
- **画布选区（Marquee/Path）**：由选区工具产生的像素级/矢量选区，是像素操作的作用蒙版（[INF]，对应工具：矩形选框 M / 套索 L / 魔棒 W / 钢笔 P）。

## 3. 历史/撤销栈（History Stack，[OBS] + [INF]）

- 右侧「历史记录」面板（[OBS] `panelhead: 历史记录色板≡`）证明存在**线性历史栈**。
- 交互推断：每次「提交式」操作（绘制一笔、变换、调色）压入一个历史节点；点击历史节点可跳回。
- 与 Photoshop 一致，为**快照/动作链表**式撤销（非线性、可分支跳转），非简单 Undo/Redo 双栈（[INF]）。

## 4. 数据流（用户操作 → 状态 → 视图 → 持久化，[INF]）

```
用户事件(指针/键盘)
   │  (命中测试定位到画布坐标/图层)
   ▼
控制器: 根据「当前工具 + 选项栏参数 + 选中态」计算变更
   ▼
文档模型变更: 修改图层像素/矢量/属性  →  压入历史栈
   ▼
渲染: 合成器重绘 <canvas>(含图层混合、变换、蒙版)
   ▼
视图刷新: 仅重绘脏区域(脏矩形)以提升性能
   ▼
持久化: 按需导出 PSD/PNG…；Photopea 默认本地运行，不上传原图([DOC] 官网称 Fully Local)
```

### 4.1 关键特征
- **本地优先 / 无强制云端**：Photopea 官网明确「No uploads, runs on your device, using CPU and GPU」([DOC])。因此数据流中**没有持续的云端同步环节**，与 Canva 的「实时存云」形成鲜明对比（见 `01/02-canva` 与 `04-comparison.md`）。
- **渲染与模型分离**：模型变更先发生，渲染是「读模型后合成」，二者解耦，便于做撤销/重做与性能优化。

## 5. 与 Canva 的数据流对比（预告）

| 维度 | Photopea | Canva |
| --- | --- | --- |
| 持久化 | 本地优先，导出文件 | 实时云端自动保存 |
| 撤销模型 | 历史栈（可跳转） | 产品级 Undo/Redo |
| 文档内核 | PSD 等价 | Canva 自有设计文档（页面+元素） |
| 协作 | 弱（单用户本地） | 强（多人实时） |

详见 `04-comparison.md`。
